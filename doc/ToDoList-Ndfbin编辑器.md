### 阶段 3 —— 安全网

**目标**：降低玩家误操作造成的损失。

- [x] **3.1** 撤销与重做
      说明：`ndfbin_decks/ndfedit/history.py`。未采用命令模式，而是**脏状态
      差分**——每次改动后重扫「哪些字段偏离原值」与上次快照比对。
      理由是改数据的落点有六处，命令模式任何一处漏上报就与真实状态错开，
      而错开的后果（撤销后文件停在无人预料的状态）比没有撤销更糟。
      底栏 `[撤销] [重做]` + `Ctrl+Z` / `Ctrl+Y`；批量改 150 条为一步。
      顺带修复：面板「撤销这一条的全部改动」原先不发 `dirtyChanged`，
      导致数据退回去了但状态栏与按钮仍显示未保存。
- [x] **3.2** 写回前校验
      说明：`core/writer.py` 在重建后重新执行一次 `decode`，失败则拒绝写入，
      原文件保持不变。该方式比逐条规则校验更严格——解码器本身即最完整的校验器。
- [x] **3.3** 自动备份
      说明：首次保存生成 `.bak`，内容为原始文件，此后不再覆盖。
- [x] **3.4** 失败处理与过期保护
      说明：另有过期快照保护（`StaleDocumentError`，无绕过开关）：
      文件被其他程序修改后拒绝保存，不覆盖他人的改动。

## 五、格式要点

```python
# compression_mode: 1=LZ4, 2=zstd(主力), 3/128=zlib
size = struct.unpack_from('<I', raw, 40)[0]
assert size + 40 == struct.unpack_from('<Q', raw, 0x20)[0]   # 决定性校验
body = zstandard.ZstdDecompressor(max_window_size=256*1024).decompress(
    raw[44:], max_output_size=size, allow_extra_data=False)  # 起点是 44
```

- `28 B5 2F FD` 是 zstd 帧魔数，不是 LZ4
- 写出使用 zstd level 6
- 引用键名：标量 `obj_ref` 的 id 在 `object_id`；列表元素在 `items` 下
- `obj_ref`（`0xBBBBBBBB`）为本文件内下标，`trans_ref`（`0xAAAAAAAA`）
  为 IMPR 前缀树节点号，两者不可互换

## 八、沿革说明

1. **格式逆向已在 `core/cndf_codec.py` 中完成并验证**（60 / 60 文件）。
