## 三、解决的两个问题

### 问题 1：无改动保存也会改字节

**现象**（实测 984 个文件时发现）：

```
byte-identical : 906/984
semantic-equal : 984/984
```

78 个文件的解压后 body **完全相同**，但压缩字节不同——
游戏引擎的 zstd 编码器与我们不是同一个实现。

**后果**：玩家打开文件、什么都没改、点保存 → 文件 MD5 变了，
diff 工具全红，创意工坊上传被识别为全量重写。

**解决**：`write_bytes()` 短路——无改动时直接返回**原始字节**：

```python
if not force_recompress and not changed_sections(doc, replacements):
    return doc.raw_data          # 原样返回，不重压缩
```

**效果**：1391/1391 字节一致。

> **诚实说明**：短路是唯一让这个数字成立的机制。
> 底层重压缩**仍然不可位复现**，这没关系——
> 游戏读的是解压后的图，不是字节。但任何绕过 writer 的写回都会重新引入问题。

### 问题 2：原本没有文件级写入

**现象**：`rebuild_sections()` 只返回 `bytes`，没有落盘能力。
直接覆盖游戏可能正在读的文件，是 mod 被毁的经典路径。

**解决**：`write_file()` 四重保护

```
1. 校验    重建结果重新 decode 一遍，失败则拒绝（原文件不动）
2. 备份    <name>.bak 写一次，永不覆盖 → 首次保存保留原始文件
3. 原子    同目录临时文件 → fsync → os.replace（Windows 上原子）
4. 清理    任何异常路径都删掉临时文件
```

### ★ 问题 3：过期快照会静默回滚文件（端到端测试时发现）

**发现过程**：第一次跑端到端演示，编辑明明成功写入了，但重新读回却是**旧值**。

**根因**：`doc.raw_data` 是**打开文件那一刻**的快照。
`write_bytes(doc, {})` 的短路返回的就是这个快照。
于是「先改一次保存 → 再用同一个 doc 做一次无改动保存」
会把文件**还原成打开时的状态**——编辑被静默撤销，没有任何报错。

**危害等级**：🔴 这是最容易丢用户工作的一类 bug——
不是崩溃，不是报错，而是"看起来成功了但改动没了"。

**解决**：`write_file()` 增加**过期快照检测**

```python
if before is not None and before != doc.raw_data:
    raise StaleDocumentError(...)      # 拒绝写入，附明确补救说明
```

**不提供绕过开关**——`allow_stale` 我先加了又删掉：
它会在"无改动"路径上重新引入同一个回滚问题。
补救方式只有一个且成本很低：**重新 decode**（一次解析，不丢任何东西）。

测试固定了这个设计：`test_no_bypass_flag_exists` 断言
`write_file` 签名里不存在 `allow_stale` / `force` / `overwrite`。

## 四、API 速查

```python
from ndfbin_decks.core import cndf_codec, writer

raw = open(path, 'rb').read()
doc, decoded = cndf_codec.decode(raw, source=path)

# --- 只读：什么都不改 ---
writer.write_bytes(doc, {})            # 返回原字节（同一对象）

# --- 编辑：改一个段 ---
repl = writer.sections_of(doc)         # {段名: bytes}
repl['OBJE'] = cndf_codec.encode_objects(decoded['objects'])
res = writer.write_file(path, doc, repl)
print(res)                             # WriteResult(..., identical=False,
                                       #   recompressed=True, 265675->265812)

# --- 安全检查：只验证不落盘 ---
res = writer.write_file(path, doc, repl, dry_run=True)

# --- 保存后要继续改？重新 decode 刷新快照 ---
doc, decoded = cndf_codec.decode(open(path,'rb').read(), source=path)
```

| 函数 | 用途 |
|---|---|
| `write_bytes(doc, repl, force_recompress=False)` | 生成字节；无改动返回原字节 |
| `write_file(path, doc, repl, backup=True, dry_run=False)` | 原子落盘，返回 `WriteResult` |
| `sections_of(doc)` | 全部段 → `{名称: bytes}` |
| `changed_sections(doc, repl)` | 哪些段真的变了（空集 = 无事发生） |
| `sha256(data)` | 摘要助手 |

`WriteResult` 字段：`path` / `byte_identical` / `recompressed` /
`backup` / `size_before` / `size_after`

异常：`StaleDocumentError`（快照过期，必须重新 decode）

如果游戏对字节层面有额外要求（如校验和、压缩器指纹），
