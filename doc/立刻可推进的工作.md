### 打开

- 任意 `.ndfbin`，不限 Weapon
- **Mod 两级选择**：本机 ModGen 工作区与 Steam 创意工坊自动发现，手动目录兜底
- 实测本机 16 个 Mod、133 个 ndfbin；扫描全部 Mod 耗时 0.02 秒

### 看

| 能力 | 说明 |
|---|---|
| 通用三栏 | 类（源自 PROP 表）→ 对象 → 字段，更换文件无需配置 |
| 对象标签 | 五级回退：导出名 → 文本字段 → 哈希前 8 位 → `F族-级` → 借引用者标签 → `#id` |
| 弹药视图 | 弹种与 GUID；装备名错配问题已修正 |
| 实体聚合视图 | 血量 / 装甲 / 速度，按 8 个语义分组跨模块聚合，标注共用情况 |
| 引用使用者追溯 | 候选列表中说明该目标被多少实体间接使用 |

### 改

| 能改什么 | 覆盖范围 |
|---|---|
| 标量 | int / float / bool |
| 引用（本文件对象） | 装甲等级、伤害类型、命中规则、弹药。长按钮可**进到目标对象**去改它自己的字段 |
| 克隆对象 | 复制一个对象、换新 GUID、追加到对象表与顶层表，再让别的字段改指向它 |
| 引用（跨文件路径） | 单位、地形速度因子、外挂模块 |
| 一串引用 | 牌组载具槽位、炮塔挂载、模块列表。**可增删项、调顺序**，每项能「查看」目标对象 |
| 补加缺失字段 | 覆盖率 <100% 的属性可以补进没有它的对象 |
| 字符串（名字 / 特效） | 换成文件里已有的名字，列表按使用次数排序。`ImpactHappening` 这类 |
| 一串字符串（标签） | `TraitsToken`：可换、可增删、可调顺序 |
| 哈希（照抄） | `Name` / `Caliber` / `TypeCategoryName`：不可逆，只能照抄同类对象用过的值 |
| **按值筛选后批量改** | 弹药专用页：条件可增删，选中字段一次改成同一个值 |

以上每一类都能**撤销**：底栏 `[撤销] [重做]` 或 `Ctrl+Z` / `Ctrl+Y`。
批量改 150 条是一步，一次撤回。撤销范围是「打开这个文件时」，
换文件或保存后重置（保存是提交点，不是可撤销操作）。

### 存

原子写 + 一次性 `.bak`（永不覆盖）+ 写前二次 decode 校验 + 过期快照保护。

## 三、已确认的事实边界

以下四项均经实测确认。变更方案前需先推翻对应证据。

1. **`loc_hash` 不可逆。** 三条证据：
   - 值存于 `value_hex` 而非 `value`
   - `io/localisation.py` 注释记载：约 40 种哈希 × 6 种编码均无法复现
   - Mod 内 26 个 `.dic` 分属四族（UNITS / PLATOONS / COMPANIES / INTERFACE），
     **无弹药族**；且 WARNO 无官方中文（7 种语言，无 CN/ZH）
   结论：弹药标签采用「弹种 · GUID 前 8 位」，不使用中文名。
2. **属性名保留英文。** 游戏内显示同为英文，翻译会导致界面与游戏不一致。
   中文说明置于文档，不进界面。
3. **两类引用不可互换。** `obj_ref`（`0xBBBBBBBB`）为本文件内下标，
   `trans_ref`（`0xAAAAAAAA`）为 IMPR 前缀树的节点号。两者编码与语义均不同，
   混用会产生看似合理但语义错误的引用。
4. **`obj_ref` 改目标须同时修改 `class_id`。** `decode` 会校验两者自洽，
   仅修改其一会导致整个文件无法解码。测试中已构造该错误以证明校验存在。

#### ⑥ 撤销与重做命令栈（1~2 天）—— ✅ 已完成

底栏新增 `[撤销] [重做]`，快捷键 `Ctrl+Z` / `Ctrl+Y`（外加 `Ctrl+Shift+Z`）。
批量改 150 条**是一步**，一次撤销全部退回。

实现上刻意**没有用命令模式**：改数据的落点有六处（标量、实体聚合行、
换引用目标、换列表某一项、补加/摘掉字段、批量设值），任何一处漏上报，
栈就和真实状态错开——而错开的后果是撤销后文件停在一个谁都没预料到的
状态，比没有撤销更糟。改成 `ndfbin_decks/ndfedit/history.py` 的
**脏状态差分**：每次改动后重扫「哪些字段偏离了原值」，与上次快照比对。
不可能失同步，且批量改天然一步。

这一步顺带修掉一个真实缺陷：面板上的「撤销这一条的全部改动」原先
**不发 `dirtyChanged` 信号**，于是数据退回去了、状态栏还写着
「已改动 1 个对象」，保存按钮亮着、按下去却因为 `dirty_count` 为 0
而静默什么都不做。现在它既刷新界面，也会**记进历史**（可再用 `Ctrl+Z` 退回）。

**验收**（`tests/test_history.py` 139 项全过）：`Ctrl+Z` / `Ctrl+Y`
可连续回退与重做，跨对象亦成立；随机 26 次操作退到底后
`encode_objects` 与打开时**逐字节相同**。

## 六、建议的第一步

**P1 已清空，② 打包也已交付，剩下的全部工作都排在 ① 游戏内真机验证之后。**

依据：

- 当前已具备的修改能力中，**引用与列表引用修改的是对象图**，风险高于修改数值，
  而此类错误在「可解码」层面不可见，只有游戏内验证能暴露。
  最直接的例子：把 `TBlindageProperties.ResistanceFront` 指向一个
  `TTagsModuleDescriptor`，`class_id` 写对时**编码合法、`decode` 也通过**，
  但语义彻底崩坏。
- 若验证暴露问题，可能**改变后续所有功能的优先级**——现在这条链路上
  已经积了五类改动能力加一套撤销栈，任何一处不成立都会推翻后面的排期。
- ② 已经做完（0.1 出包并验证），它当初确实不依赖真机结论，也确实因此
  可以先并行推进——见 P0 ② 的实测记录。

具体做法见 P0 ①：用副本改三处（一个标量、一个引用、一个列表引用），
进游戏确认三处都生效且 Mod 正常加载，然后 `.bak` 还原验证。
